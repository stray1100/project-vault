用途与定位

对交付物的形态与质量标准约定：MD 与 HTML 双份、手机优先、离线可用、必须附实测数据。

老板专属的产出与交付规范，规定「交什么格式、落在哪、怎么命名、何时推送」，适用于所有会话的交付动作。

目的是让产物在电脑和手机两端都能直接打开、随时可查，不依赖外部资源与网络。

本说明由项目档案馆统一维护，更新项目信息后本页会同步重建。

功能模块

双份交付默认同时产出 Markdown 与 HTML 各一份，内容一致。
手机优先 HTMLHTML 为自包含单文件：内联样式、viewport 适配、无外链、可离线打开。
落盘位置中间脚本与临时数据入 temp，最终产物入 output，不写桌面等其它位置。
推送询问交付前主动询问推送到苹果手机还是安卓手机，按选择执行后再收尾。
命名规范文件名用「主题_YYYYMMDD」，同主题多次产出按日期区分。
结论先行先给结论，再用分层表格展开细节，避免长段落淹没有效信息。
可核可溯路径、数据、文号必须真实可核对，查不到就如实说明，不编造。

使用方式

  1. 产出前先定结构：结论先行，再按维度分表展开。
  2. 先写 Markdown，再据此生成同内容的自包含 HTML。
  3. 中间脚本放 temp，最终文件写 output，写完核对路径真实存在。
  4. 交付时主动问推送对象（苹果 / 安卓），按选择执行。
  5. 文件名按「主题_YYYYMMDD」命名，便于按日期检索。

边界与限制

  • 规范约束交付形式与流程，不改变内容本身的专业判断。
  • 单文件 HTML 内嵌大图或视频时体积会明显增大，需要时改用外链或分文件。
  • 推送依赖客户端与手机端可达，网络受限时需改用其它方式传文件。

常见问题

为什么一定要 HTML？

手机端可直接打开、离线可看、不依赖外部样式与脚本，比 MD 更适合随手查阅。

只给 MD 行不行？

按规范默认双份；确实只需一端的场景需先说明。

产物该放哪？

最终交付物放 output，中间脚本与临时数据放 temp，不写桌面。
